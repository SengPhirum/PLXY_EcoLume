What the installer does

The button opens the ESP Web Tools dialog, which erases the flash and writes a single merged image at offset 0x0: bootloader, partition table, OTA selector, and the EcoLume application. The image is the exact artifact published by the firmware release workflow, so a web install and a CI build are byte-identical.

Provision the controller

A freshly flashed controller carries no credentials. It holds the lamp at the safe local brightness, stays off the network, and waits to be provisioned. Open Logs & Console in the installer dialog (or any serial monitor at 115200 baud) and enter the device's own values:

set device.id    KH-PNH-004182
set device.token <the token issued when the asset was provisioned>
set apn          <carrier APN>
set mqtt.host    mqtt.example.gov.kh
set mqtt.port    8883
reboot

Each set writes straight to the ESP32's non-volatile storage and takes effect after reboot, so settings survive reboots and firmware updates. Type help for the full command list, show to review the current configuration (secrets are masked), set-ca to paste a broker root certificate, and factory-reset to erase the device identity before returning a controller from the field.

Issue a unique token per device from the operations portal. Never reuse a token across poles, and never commit one to source control.

Transport security

TinyGSM's SIM7600 driver does not implement the module's SSL stack, so this build speaks plaintext MQTT and refuses to publish until an operator explicitly accepts that with set mqtt.insecure true. Use that only on an isolated bench network. For field deployments, terminate TLS at a gateway inside a private APN, move to a modem whose TinyGSM driver implements SSL, or link a TLS wrapper over the TinyGSM client. The firmware guide covers each option and its trade-offs.

Verify the installation

  1. The console prints the firmware version, the device identity, and the broker it is dialling.
  2. The controller registers on the cellular network and connects to the MQTT broker over TLS.
  3. Within one telemetry interval (60 seconds) the asset turns ONLINE in the operations portal with live voltage, current, and power.
  4. Send a brightness command from the asset page and confirm the device acknowledges it.

Prefer a local build?

Nothing here replaces the normal workflow. The PlatformIO project is unchanged:

cd firmware
cp include/config.example.h include/config.h
pio run                 # build
pio run -t upload       # flash over USB
pio device monitor      # serial console

Values compiled into config.h act as defaults; anything stored on the device takes precedence. That lets one binary serve a whole fleet while a bench unit keeps its baked-in settings.

Before you start

  • Desktop Chrome, Edge, or Opera (Web Serial).
  • A USB data cable — charge-only cables will not enumerate.
  • CP210x or CH34x USB-serial drivers, if your OS does not ship them.
  • The board powered from USB only, disconnected from mains wiring.

If the board is not listed

  • Close other serial monitors, then unplug and replug the board.
  • Hold BOOT while the installer connects, and release it once flashing starts.
  • Try a different USB port or cable; hubs are a frequent culprit.
  • Confirm the port appears in your operating system's device list.

Safety

  • Never connect an ESP32 directly to mains voltage.
  • Use certified isolation, surge protection, and earthing on the pole.
  • A qualified electrical engineer must approve every mains-connected part.
